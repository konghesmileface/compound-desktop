# 第二大脑客户端 · 回归测试 CASE(2026-09-01 重写版)

> **为什么重写**:旧 case 全走 API/curl,给了假信心——真客户端一测全是 bug(DB锁误报、Tauri下载/媒体打不开、弹窗透明、Excel漏行、8G卡死),旧 case **一个都没测出来**。
> 新 case 的铁律:**必须真点客户端 UI + 验数据正确性 + 覆盖 Tauri 环境 + 负载下前台可用性**。curl 只能做数据对账的辅助,绝不能作为"通过"的依据。

---

## 0. 测试方法铁律(每条 case 都按这个执行)

1. **走真客户端,不走 curl**:所有"能不能用"的判定必须在打包的 Compound.app / setup.exe 里**用鼠标点**。curl 只用于事后对账(库里存了什么)。CDP 可自动化点击(Chrome + dist + 注入 `window.__COMPOUND_API_BASE__` + localStorage token);Tauri WKWebView 无 CDP,靠人点或看 sidecar 日志。
2. **验"结果"不验"返回200"**:点完要看**屏幕上真出现了对的东西**——文件真下载到磁盘、音频真出声、Excel 真显示所有行、弹窗真看得清、关系图真有节点。200/无报错 ≠ 通过。
3. **Tauri 环境专项**(旧 case 完全没覆盖):WKWebView 里 `window.open`/`<a download>`/`<a target=_blank>` 全被拦、相对 `/api` 打不到 sidecar、`backdrop-filter` blur 常失效。凡"下载/播放/开外链/毛玻璃弹窗"都要在**打包客户端**里验,web 里过不算。
4. **负载下测**:客户端首启会跑重后台(嵌入全部数据 + 逐个建 intel/关系卡),8G 机会被占满。**在后台分析进行时**去点前台功能(存卡片/资料/群图),看会不会撞 DB 锁 / 超时 / 转圈不出。这是最容易漏、也最容易挂的场景。
5. **数据正确性对账**:入库类必须查库确认**提取完整**(不是只取了标题/表头/首行)。`SELECT length(text) FROM pages` 对比源文件体量。
6. **边界四态**:①无 AI key ②断网/墙内(github/HF 不通)③空库(全新账号)④首启(模型未下载/后台分析未跑完)。每个功能在这四态下的表现都要看(至少友好报错,不能白屏/崩)。

## 3. 数据正确性矩阵(入库→文库查全文,不是只看能不能开)

每格式:造一个**含唯一哨兵词 + 多行/多页**的样件 → 入库 → ①文库点开看全文 ②`SELECT length(text),substr(text,1,80) FROM pages` 对比源文件体量 ③搜哨兵词命中。

| 格式 | 重点验 | 易挂 |
|---|---|---|
| txt/md | 全文+分块 | — |
| **xlsx/xls** | **所有数据行(不只表头/工作表名)** | dimension声明错漏行(已修) |
| **csv** | 所有行 | 大文件截断 |
| pdf(文本层) | 全页文字 | 扫描版需OCR |
| pdf(扫描/图) | OCR文字 | rapidocr没触发 |
| docx | 全段落+表格 | 表格漏 |
| pptx | 每页文字 | 备注漏 |
| html | 正文(去标签) | script混入 |
| eml/mbox | 中文正文不乱码 | 无charset(已修_safe_body) |
| epub/mobi/azw3 | 全书文字 | fitz变体 |
| 图片(png/jpg/heic) | OCR文字 | HEIC崩(已修) |
| 音频(mp3/m4a/wav) | 转写文字 | SenseVoice首启下载(Win) |
| 视频(mp4/mov) | 转写+关键帧OCR | ffmpeg |
