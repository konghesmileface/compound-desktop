> 角色:高级测试经理视角。目标 = 对"第二大脑"桌面客户端做**最全面完整**的测试体系:
> 功能测试 / 单元-模块测试 / 集成测试 / 系统(E2E)测试 / 回归测试 / 性能-负载 / 安全-隐私 / 兼容性 / UI-UX / 异常-边界 / 数据正确性。

## 1. 被测系统(SUT)架构 —— 测试必须三层都覆盖

| 层 | 位置 | 职责 | 测试关注 |
|---|---|---|---|
| **客户端** | Compound.app / setup.exe(Tauri壳 + 本地 sidecar FastAPI + 前端) | 本地优先:数据/模型/OCR/嵌入全本地 | UI交互、Tauri环境、本地库、离线、8G负载 |

## 3. 测试级别(L1→L5,逐级向上)

### L1 单元 / 模块测试(组件/函数隔离)
- **后端模块**:extract.py(每格式提取,§3矩阵)、ingest.py(db_connect/WAL/autocommit、trigram迁移)、semantic.py(embed_profile按内存分档、embed_pending)、model_bootstrap.py(缺失检测/OSS下载/多镜像回落)、llm.py(_friendly_err人话化、双模型)、generate.py(officecli render/flush)、model_bootstrap、social(_share_persona/_fetch_friend_persona)。
  - 手段:`--selftest`(冻结包断言所有依赖+数据文件在)、造样件直调函数(如 `extract._xlsx` reset_dimensions 对多行文件、`_safe_body` 对无charset邮件)。
- **前端组件**:每个 .jsx 的 props/空态/错误态渲染(空库→空态非崩;无数据→占位)。
- **DoD**:selftest PASS;每格式提取字符数>阈值;各函数边界(空/超大/异常)不崩。

### L2 集成测试(模块间 + 客户端↔云)
- sidecar ↔ 云 compound-server:登录/支付/好友代理(_cloud_proxy 绕系统代理直连)。
- 前端 ↔ sidecar:所有 /api 走模块级 fetch 影子 + apiUrl(Tauri origin)。
- 嵌入 ↔ 检索:embed_pending 产向量 → 语义问答/星图能用。
- handoff:微信助手写 ndjson → sidecar 消费线程入库。
- **DoD**:跨层调用通、鉴权贯通、代理场景不挂。

### L3 系统 / 端到端测试(真实用户旅程)
- 11 条端到端流程(见 CASES §9 F1–F11):新用户上手/全格式入库/微信实时/iPhone导入/★好友姻缘/定期同步/目标/产出文档/支付/账户/冥想。
- **DoD**:每条流程从头走到尾,屏幕真出对的结果,无一环断。

### L4 回归测试(已修不复发 + 未受影响功能没坏)
- 本轮 9+类缺陷(见 §7)逐条复测**在修复版包上**——不是旧包。
- 每次发版跑全套 §2+§9,防止新改动打破旧功能。
- **DoD**:9类缺陷全不复现;历史功能(全格式/微信/画像/雷达)仍通。

### L5 验收测试(用户视角,产品价值)
- 用户(产品负责人)手点核心场景:能不能真用、好不好用、有没有意义。
- 重点:好友/姻缘"真能用"(非本地恰好有数据的假象)、产出文档专业排版、隐私可信。
