## TAB 1:入库(Ingest)

### 1.1 选文件入库
- 前置:已登录
- 步骤:入库页 → 点「选择文件」→ 选 1 个 PDF → 确认
- 预期:出现进度条 → 完成 → 文库里出现该文件,可搜到内容
- 验证点:/api/upload 返 job_id;/api/job 轮询到 done;pages 表有该 doc 的页;FTS 搜正文命中

### 1.2 选文件夹入库
- 前置:已登录;准备一个含混合格式(pdf/docx/图片/mp3)的文件夹
- 步骤:点「选择文件夹」→ 选文件夹 → 确认
- 预期:文件夹内所有支持格式并发上传 → 各自入库;不支持的被前端过滤
- ⚠ 验证:大文件夹(10+)进度正确;各格式走对提取路径(method 字段)

### 1.3 多格式覆盖(逐格式各 1)
- 文档:pdf/epub/docx/pptx/xlsx/md/txt/csv/json/html/eml/mbox → 入库后搜到正文
- 图片 OCR:png/jpg/webp/bmp/gif/**heic** → 入库 method=ocr:rapidocr,识别出文字
- 音频:mp3/wav/m4a → method=asr:sensevoice,转写出文字
- 视频:mp4/mov → 抽音轨转写 + 关键帧 OCR
- ⚠ HEIC 必须成功(iPhone 默认格式);azw3 需 mobi 转换

### 1.4 URL 抓取
- 步骤:入库框粘贴网址 → 回车/点「抓取入库」
- 分支:①普通网页→提取正文 ②视频站(B站/YouTube)→yt-dlp 下载转写 ③直链 PDF/音频→按 Content-Type 入库
- ⚠ 验证:SSRF 防护(粘 http://127.0.0.1 应被拒);视频 >800MB 会截断

### 1.5 ★OCR 后端切换(含 T430)
- **auto**(默认):数字版走文字层,扫描页自动 rapidocr
- **rapidocr**:强制本地 OCR
- **★t430**:前置 = T430 服务(172.16.11.199)在;配 ocr_url/T430_OCR_URL → 扫描页 POST 到 T430
  - ⚠ 关键验证:T430 连不上时 method=t430-unreachable,页内容为空(不自动回落本地)—— 确认这个行为,用户要知道
- 步骤:上传同一扫描 PDF,分别用 auto / rapidocr / t430,对比 method 和识别结果

### 1.6 音视频解析深度
- 前置:准备多人对话音频
- 预期:SenseVoice 转写逐字;≥2 人时说话人分离标「说话人N」;视频关键帧 OCR 出画面文字
- ⚠ 模型缺失时优雅降级(不崩,但用户可能不知为何空)

### 1.8 ★★微信助手实时同步(入库页 WechatSync 组件,核心功能,完整端到端流程)
> 助手是独立 app(客户端下载中心提供 3 平台包),负责解密微信→写 handoff;客户端消费 handoff 入库。
> 这条是**杀手功能**,必须整条走通,每步验证。已在 B 机真机跑通(8716 条真微信)。

**1.8.1 下载助手(客户端下载中心)**
- 步骤:入库页 → 实时同步区 → 看到「先下载微信同步助手」+ 3 平台按钮(Windows/Mac Intel/Mac Apple)
- ★验证:下载框有**显著 4 步引导**(下载→安装打开→**抓密钥**→开始同步),第3步抓密钥橙色警示「不做会同步到空」(本轮加的 UX)
- 点对应平台按钮 → 从本机 /dl 下载(离线,不连云)→ 得到 .dmg/.exe
- 验证:selftest 确认包内有 3 个助手安装包;/dl/ 能下

**1.8.2 安装助手**
- Mac:挂载 dmg → 拖「微信同步助手.app」进应用程序 → 首次右键打开放行
- 验证:~/Applications/微信同步助手.app 存在

**1.8.3 打开助手 + 控制面板**
- 步骤:打开助手 → 菜单栏出现;面板服务起(8767)
- 验证:curl 127.0.0.1:8767/api/status 返回 {running,keys,today,cap_active,cap_msg}(cap 字段=本轮加的抓密钥进度)
- 面板有「抓取/更新密钥」+「开始实时同步」按钮

**1.8.4 ★抓密钥(Mac:重签注入微信)**
- 前置:电脑版微信已装
- 步骤:面板点「抓取/更新密钥」→ 助手重签注入一份托管微信并启动 → **用户在托管微信里登录 + 搜索框搜个词**(触发打开全部聊天库)→ hook 抓到 per-db key
- ★验证进度(本轮加的):点后面板出现绿色脉冲横幅,依次显示「正在准备重签微信…」→「★微信已打开→请登录+搜词」→「已拿到 N 个密钥」→「✓ 抓取完成 N 个」;keys 从 0 变 N
- ⚠ 边界:不抓密钥直接点「开始同步」→ keys=0 → handoff 空 → 同步到空(本轮实测的坑,已加引导)
- ⚠ Windows:走 frida hook setCipherKey(退登再登触发),不是重签
- 验证:/tmp/cckeys.txt 有 key;~/.wxsync/keys_captured.json 生成

**1.8.5 开始实时同步(助手侧)**
- 步骤:面板点「开始实时同步」
- 预期:running=true;助手增量解密微信→写 ~/.wxsync/handoff/messages-YYYYMMDD.ndjson
- 验证:handoff 文件字节增长;面板 today 计数涨;recent 列出真实最近消息

**1.8.6 客户端消费 handoff 入库**
- 步骤:客户端入库页挂载即自动 api.wechatWatch()(设 _HANDOFF_OWNER + 起消费线程)
- 预期:sidecar 消费线程逐行读 handoff(4MB/tick,字节游标持久化)→ 指纹去重 → 入库
- ★验证:注入/真消息 3-5s 内 → wechat 页数增加;FTS 搜到该消息;按会话分文档「微信_与XX.txt」
- 已验证:B 上 8716 条 → 71 文档/221 页/8647 wechat_lines

**1.8.7 前端实时状态(呼吸球四态)**
- detect(检测中)/ importing(导入历史 hist_pct%)/ live(实时同步中)/ waiting(等待客户端)
- ★验证:助手在跑+有新消息→「实时同步中」绿;关助手 15s 后→「等待客户端」橙(心跳门控)
- ⚠ 心跳:只有 ~/.wxsync/state.json 15s 内更新才 beat,否则回落等待(防误报"实时中")

**1.8.8 断线重连/去重**
- 步骤:关助手→再开;或客户端重启
- 预期:游标续读不重复(compound_cursors.json 持久化 + wechat_lines 指纹双保险),不丢不重

**1.8.9 消费入库后 → 自动分析**
- 预期:bg-embed 嵌入 + bg-analyzer 跑 intel/entities → 人脉/雷达/洞察自动出数据(需 LLM key)
- 已验证:B 上承诺雷达/人脉图谱自动 0→100%

**1.8.10 助手退出真停**
- 步骤:助手托盘点「退出」
- 预期:launchctl unload com.wxsync.decrypt + 杀 worker,真停(不被 launchd 重启)
- ⚠ 常驻是设计(保持默认),只验证「退出=真退」(本轮修复)
